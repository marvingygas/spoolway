The observer, watched watching

Two tasks that talk for a long time, so that the backgrounded observer has something to read — and so that the one thing nothing else in this project tests, a command step that outlives the task that started it, is looked at.

Context

scripts/e2e/observe.sh is started by a run: step with background: true, and everything interesting about it happens after the step that started it is over: it takes a lock, keeps reading spoolway lane, and is stopped by the dispatcher when its task is archived. A suite could assert the lock. Only a run can say whether what it wrote down was worth reading.

  • scripts/e2e/observe.sh — the lock, the poll and what it appends
  • src/command_step.rs — what a run: step does, backgrounded and not

Decisions

The observer reads panes the way a person does

An observer talking to the multiplexer directly would see more and prove less: what a plan run is checking is the surface a person actually has, which is spoolway lane. The cost is that a pane the CLI cannot read is a pane the observer misses, and that is the correct blind spot to have.

Read observations.md while the run is going, not after. A record of a run you already watched is a much weaker thing than one arriving beside you.

Consequences

What you see

  • A file filling up in the project root with one line per lane per change — which is also the only artefact a plan run leaves behind for somebody who was not there.
  • The hand-off: the first task's observer dies with its task, and the second task's takes the lock and keeps appending to the same file.

What it costs

  • Nothing restarts an observer that dies for any other reason. The lockfile is what you check, not what warns you.
  • Two tasks asking for prose is the slowest of these four plans, because prose is what a small local model is slowest at.

The 2 tasks

Each task asks a local model for a behaviour rather than for work. What is being tested is spoolway's answer to that behaviour, not the model's answer to a problem.

  1. writes-doc

    waits on nothing

    Writes a section of docs/cli.md — a long turn, on purpose.

    Done when

    • the document gains three sub-headings
    • the domain block is untouched

    Never

    • never touches src/
    • never rewrites what is there
    • docs/cli.md

  2. reads-doc

    waits on writes-doc

    Summarises that section in notes.md, and closes the plan out.

    Done when

    • notes.md gains a paragraph
    • docs/cli.md is not edited

    Never

    • never edits the document
    • never reads observations.md
    • notes.md

Before anything is queued

Queue this by naming its path: scripts/e2e/queue-plan.sh scripts/e2e/plans/observer.html (or open spoolway queue and select its cards from the screen instead), from the project scripts/e2e/scaffold.sh --plan observer built. It is not a plan for this repository and must never be queued into it.
