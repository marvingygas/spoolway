# the tips the dispatch tab shows on its last row, one per line. the board
# shuffles them. a tip is one plain lowercase sentence of at most 69
# characters. after a bar, a line names what it explains: a key on a tab's
# key line, a config setting, a pipeline or step key, or a task key. the
# board draws only the text before the bar.

# the dispatch tab
enter starts dispatching here. press it again to stop. | key dispatch enter
r resumes the task under the cursor. it shows only when it can. | key dispatch r
r opens the resume picker. pick any step to resume the task there. | key dispatch r
pick done in the resume picker to close a task that cannot pass.
the NEXT column shows where r would send a stopped task.
r and o work even when no dispatcher is running.
o on a task opens its menu: open, pause, focus, restart, unqueue. | key dispatch o
o then open task opens the task file in your editor.
o then open plan opens the plan page the task was cut from.
o then focus brings that task's pane to the front.
o then pause can wait until the current step finishes.
o then restart runs the step again with a fresh chat.
o then unqueue moves a task back to pending.
unqueue deletes a started task's local branch and worktree.
u loads your config changes into the running dispatcher. | key dispatch u
quitting stops dispatching here, but running lanes keep working. | key dispatch q
k skips a failed issue hook. r runs the hook again.
a dim ↻ 3 beside a step means the task is there for the third time.
the spool beside the name turns while a dispatcher is running.
RECENT lists the moves tasks made, newest first.
slots 1/∞ means that agent has no concurrency cap.
"1 held" on a slots line is a slot kept free for a started group.
a task file that does not parse is named in amber under the board.

# moving between tabs
number keys switch tabs. the strip shows each tab's number.
q quits spoolway from any tab. | key * q
dispatching keeps running while you look at other tabs.
a project set up in home mode has no overrides tab.

# the queue tab
space ticks a group on the queue tab. | key queue space
enter on the queue tab queues every group you ticked. | key queue enter
o on the queue tab opens a menu to change a pending task. | key queue o
f searches the queue tab. enter keeps the results, esc clears. | key queue f
h on the queue tab shows or hides done tasks. | key queue h
writing a task file does not queue it. queue it on the queue tab.
queueing moves a group's tasks out of pending and into the queue.
tasks you queue while dispatching start on the next pass.
a group is one chain. each task waits for the one before it.
a group can wait for another group: o then edit depends on.
o then edit lands in changes the branch a group's work lands in.
o then edit pipeline moves a pending task to another pipeline.
o then gate pauses one task after a step you pick.
o then trial runs one group on several pipelines to compare them.
o then save as routine keeps a group to queue again later.
a task waits until the task it depends on is done and archived.
a dependent task branches off its dependency, so pull requests stack.
a row saying use /spoolway-tasks is a plan not cut into tasks yet.
do not delete queue files by hand. unqueue the task instead.

# the routines tab
space ticks a routine on the routines tab. | key routines space
enter on the routines tab queues the routines you ticked. | key routines enter
o on a routine edits its schedule, turns its job off, or deletes it. | key routines o
o then edit schedule makes a routine run on a timer, as a job.
jobs fire only while a dispatcher runs. missed times are skipped.
dispatching started here stays up on an empty queue, so jobs fire.
a routine runs one copy at a time.
deactivating a job keeps its schedule for later.

# the overrides tab
overrides change settings for this machine only, never the repo.
← and → switch sections on the overrides tab.
enter on a config key in overrides sets your own value for it. | key overrides enter
enter on a prompt in overrides copies it so you can edit your own.
the pipeline section of overrides sets one field on many steps.
f searches the list on the overrides tab. | key overrides f
o on the overrides tab opens the menu for the row under the cursor. | key overrides o
w opens your private overrides folder. | key overrides w
space ticks a key in the active section of the overrides tab. | key overrides space
a ticks every key in the active section. | key overrides a
promote, in the active section's menu, moves overrides onto a branch.

# the eval tab
the eval tab reads the lane ledger: what each lane ran and cost.
→ on the eval tab moves between the lanes, dirs and trials tables.
enter on the eval tab's trials table opens a trial. | key eval enter
a on the eval tab picks a column to sort by, smallest first. | key eval a
d on the eval tab picks a column to sort by, largest first. | key eval d
t on the eval tab flips between totals and per-task figures. | key eval t
f on the eval tab opens the filter panel. | key eval f
e exports the eval table on screen to a CSV file. | key eval e
r on the eval tab reads the ledger again. | key eval r

# task files
a task's id: becomes its file name, its branch and its lane name. | task id
a task's title: is a commit line, such as feat(queue): add a flag. | task title
group: names the chain of work a task belongs to. | task group
pipeline: picks which pipeline a task runs on. | task pipeline
depends_on: makes a task wait until another task is done. | task depends_on
base: is the branch a task's work lands in. | task base
starts_from: cuts a task's worktree from another branch. | task starts_from
gate_at: pauses one task after a step, for you to resume. | task gate_at
plan: holds the plan page path. o then open plan opens it. | task plan
source: holds the URL of the issue a task came from. | task source
tracking: off runs no issue hook for that task. | task tracking
ticket: holds the tracker's ticket id for a task. | task ticket
epic: holds the tracker's epic id for a task's group. | task epic
group_description: is the text of the group's tracker issue. | task group_description
labels: adds labels to a task's tracker issue. | task labels
complexity: is a 1 to 100 guess, shown beside the cost in eval. | task complexity
every task works in its own git worktree, never in your checkout.
quote a task title that holds ": " or the file will not parse.

# pipelines
the first step in steps: is where every task starts. | pipeline steps
steps lower in a pipeline file get free slots first.
raise a pipeline's version: after a change, to compare runs. | pipeline version
a pipeline's description: says in one line what it is for. | pipeline description
a step's description: is a one-line note on what it does. | step description
task_template: picks the task skeleton a pipeline's tasks use. | pipeline task_template
a step's id: is written into a task's stage:, so rename with care. | step id
agent: on a step makes it an agent step, run by that profile. | step agent
prompt: names a step's prompt file. it defaults to the step id. | step prompt
model: is required on every agent step. | step model
effort: sets how hard a step's model thinks. | step effort
skills: runs those skills at the top of a step's first prompt. | step skills
session: true lets a step continue an earlier step's chat. | step session
slot: false lets a step run without using an agent slot. | step slot
gate: on a step makes a person check its outcome first. | step gate
on_pass: names the step a task moves to when a step passes. | step on_pass
on_fail: names where a fail goes. without it, the task blocks. | step on_fail
loop: caps how many times a task may arrive at a step. | step loop
run: makes a step a command step. its exit code is its outcome. | step run
timeout: kills a command step after that long. 30m by default. | step timeout
background: true lets a task move on while its command runs. | step background
hide: true runs a command step without a pane. | step hide
first: runs a step only on the first task of a chain. | step first
last: runs a step once per chain, on its top task. | step last
serial: true runs a command step for one task at a time. | step serial
every step runs for every task. optional steps need another pipeline.
command steps cannot be gated. gate the agent step after them.
a gate still waits for a person in an unattended run.
a running dispatcher ignores pipeline edits until you press u.
prompt edits need no reload. each lane reads its prompt as it starts.
the default and bugfix pipelines are samples. change them freely.

# lanes
a lane is one agent working one step of one task, in its own pane.
each task gets its own herdr workspace, named spoolway/<task>.
finished lanes stay open, and you can still type into them.
a row reading prompt waits on a permission question in its pane.
esc typed into a lane's pane pauses its task on the next pass.
after a pause, typing into the lane's pane resumes the task.
a lane that answers three reminders without a report is paused.
a paused task frees its slot for other tasks.

# when something stops
stopping tears nothing down. the next run picks every lane back up.
interrupt them now pauses running tasks until you dispatch again.
a gate pause means a step finished and waits for your go-ahead.
to see why a task blocked, read its status log: o then open task.
leaving blocked resets every step's loop count to zero.
pausing a command step kills it. resuming runs it from the start.
only you can resume a task. its own lane cannot.
if your checkout has a task's branch out, switch away, then resume.

an agent's session_reuse_ctx reuses a chat only below this % full. | config agents.<profile>.session_reuse_ctx

config changes reach a running dispatcher on its next pass.

# commands
most board actions have a command too. run spoolway --help.
spoolway doctor checks that your pipelines can run on this machine.
spoolway lane "<task> · <step>" prints what a lane has been doing.
spoolway queue route <task> shows a task's steps and its next stop.
spoolway task contract --from <dir> checks tasks without queueing.
spoolway issue show <ref> reads one issue through your tracker hook.
spoolway pipeline copy makes a pipeline only your machine sees.
after spoolway update, run spoolway sync in each project.
spoolway whats-new prints the release notes, even offline.
dispatching needs herdr. open herdr, then run spoolway inside it.
one dispatcher per project. a second one says one is already running.

# issues and pull requests
spoolway never merges. landing each pull request is your call.
the github.sh and jira.sh hooks are samples you can edit.
unqueue keeps the pushed branch and its pull request.
